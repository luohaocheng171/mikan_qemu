一、基础参数 (-m, -smp, -name, -uuid)
================================================================================

1.1 -m (内存配置)
格式: -m [size=]megs[,slots=n,maxmem=size]

★ 优点:

简单直观，最常用

支持内存热插拔 (v2.0+)

可配置最大内存和插槽数

支持单位后缀 (K/M/G)

★ 缺点:

内存分配是静态的(除非使用热插拔)

过大内存会导致启动缓慢

Windows版本内存分配可能失败

部分架构强制内存粒度(如ARM需要对齐)

内存热插拔需要guest OS支持

★ 历史遗留:

v1.0前: 只支持 -m megs (无slots/maxmem)

v2.0: 增加slots和maxmem支持

v2.8: 支持 -m 2G 格式 (之前只支持数字)

v4.0: 增加内存气球支持

★ 常见报错:
错误: "unable to map backing store for guest RAM"
原因: 内存不足或KSM冲突
解决: 减少内存分配，关闭KSM

错误: "Cannot allocate memory"
原因: 系统内存不足
解决: 增加swap空间，关闭其他程序

错误: "invalid memory size"
原因: 内存大小格式错误
解决: 使用 -m 2048 而非 -m 2048M

★ 使用建议:

Windows 10/11: 4GB+
-m 4096

Windows XP/7: 2GB
-m 2048

内存热插拔
-m 4096,slots=4,maxmem=8G

轻量级Linux
-m 512

1.2 -smp (CPU配置)
格式: -smp [cores=]n[,threads=n][,sockets=n][,maxcpus=n]

★ 优点:

灵活配置CPU拓扑

支持CPU热插拔 (v2.8+)

可优化NUMA性能

支持超线程模拟

★ 缺点:

过多CPU导致性能下降(调度开销)

某些操作系统对CPU拓扑敏感

Windows版本可能限制CPU数量

最大255个CPU (v3.0前最多255)

CPU热插拔需要guest OS支持

★ 历史遗留:

v1.0: 只支持 -smp n

v1.4: 增加cores/threads/sockets

v2.8: 增加maxcpus

v5.0: 强制使用cores=语法

★ 常见报错:
错误: "smp: invalid CPU topology"
原因: 拓扑配置不合理 (coresthreadssockets ≠ n)
解决: 确保乘积等于CPU总数

★ 使用建议:

基本用法
-smp 4

拓扑优化
-smp cores=2,threads=2,sockets=1

热插拔支持
-smp 4,maxcpus=8

1.3 -name (虚拟机名称)
格式: -name name[,process=name][,debug-threads=on|off]

★ 优点:

窗口标题显示

进程名可识别 (Linux)

调试时可区分线程

★ 缺点:

Windows下进程名修改有限

某些版本不支持debug-threads

★ 历史遗留:

v1.0: 只支持 -name name

v2.4: 增加process参数

v4.0: 增加debug-threads

1.4 -uuid (系统UUID)
格式: -uuid UUID

★ 优点:

唯一标识虚拟机

支持迁移

某些软件需要UUID

★ 缺点:

生成正确的UUID需要额外工具

重复UUID会导致冲突

★ 使用建议:
-uuid $(uuidgen) # Linux

================================================================================
二、CPU与机器参数 (-cpu, -machine)
================================================================================

2.1 -cpu (CPU型号)
格式: -cpu model[,+feature][,-feature][,prop=value]

★ 优点:

可选择不同CPU型号

可启用/禁用特定特性

host模式获得最佳性能

支持CPU特性精细控制

★ 缺点:

错误的特性组合导致启动失败

不同QEMU版本支持不同型号

某些型号需要特定KVM版本

特性名称因版本而异

迁移时CPU必须一致

★ 历史遗留:

v1.0: 只支持基础型号(qemu32/qemu64)

v1.5: 增加core2duo等型号

v2.0: 支持+/-特性语法

v2.6: 增加host模式

v3.0: 增加EPYC等AMD型号

v5.0: 特性语法严格化

v7.0: 增加CPU拓扑控制

★ 常见报错:
错误: "CPU model 'host' not supported"
原因: QEMU版本不支持host
解决: 使用具体型号如core2duo

错误: "Unable to find CPU definition"
原因: CPU型号拼写错误
解决: qemu-system-x86_64 -cpu help 查看

★ 使用建议:

KVM最佳性能
-cpu host

兼容模式
-cpu qemu64

启用特定特性
-cpu host,+aes,+avx,-hypervisor

Windows XP兼容
-cpu qemu32,+ssse3

2.2 -machine (机器类型)
格式: -machine [type=]NAME[,prop=VALUE[,...]]

★ 优点:

灵活配置硬件平台

支持多种芯片组

可添加/移除特性

版本化机器支持迁移

★ 缺点:

某些属性需要特定版本

错误配置导致启动失败

不同架构支持不同机器

★ 历史遗留:

v1.0: -M pc (旧语法)

v1.5: 增加q35

v2.0: 增加-M q35

v2.8: 统一为-machine,增加accel属性

v4.0: 增加微虚拟机(microvm)

★ 机器类型详解:
pc - i440FX芯片组 (最兼容，v1.0+)
q35 - Q35芯片组 (PCIe支持，v1.5+)
pc-i440fx-2.8 - 版本化i440FX (迁移兼容)
pc-q35-2.8 - 版本化Q35
virt - 虚拟化专用 (ARM/MIPS)
microvm - 轻量级虚拟机 (v4.2+)

★ 常用属性:
accel=kvm|tcg|hax|whpx|hvf # 加速器选择
kernel_irqchip=on|off # 内核中断控制器
vmport=on|off|auto # VMware IO端口
kvm_shadow_mem=size # KVM影子MMU大小
dump-guest-core=on|off # core dump包含guest内存
mem-merge=on|off # KSM内存合并
usb=on|off # USB支持
hmat=on|off # ACPI HMAT (v5.0+)

★ 常见报错:
错误: "unsupported machine type"
原因: 机器类型不存在
解决: qemu-system-x86_64 -M help 查看

错误: "machine type does not support usb"
原因: 机器类型不支持USB
解决: 使用 -machine q35,usb=on 或其他支持USB的机器

★ 使用建议:

现代Windows/Linux
-machine q35,accel=kvm,usb=on

老旧系统
-machine pc,accel=tcg

迁移兼容
-machine pc-i440fx-2.8

三、存储参数 (-drive, -blockdev, -hda, -cdrom)
================================================================================

3.1 -drive (磁盘驱动器)
格式: -drive option[,...]

★ 优点:

最通用灵活的存储配置

支持多种接口和格式

可精细控制缓存和IO

支持多种后端存储

★ 缺点:

语法复杂，参数多

某些组合不兼容

旧版本支持有限

★ 历史遗留:

v1.0: 基础支持

v1.5: 增加virtio接口

v2.0: 增加aio支持

v2.4: 增加detect-zeroes

v2.8: 增加discard支持

v4.0: 增加io_uring

★ 完整参数:
file=FILE # 镜像文件路径
format=FORMAT # qcow2|raw|vmdk|vdi|vhdx
if=IFACE # ide|sata|virtio|scsi|nvme|usb|sd|floppy
media=MEDIA # disk|cdrom
index=I # 0-3 (IDE)
unit=U # 0-3
bus=B # 总线编号
cache=CACHE # writeback|none|writethrough|directsync|unsafe
aio=AIO # native|threads|io_uring (v2.4+)
discard=DISCARD # ignore|unmap (v2.8+)
detect-zeroes=DZ # on|off|unmap (v2.4+)
readonly=on|off # 只读模式
copy-on-read=on|off # 复制时读 (v1.5+)
throttling.iops-total=N # IOPS限制 (v2.10+)
snapshot=on|off # 快照模式
ifname=NAME # 网络接口名
serial=SERIAL # 序列号

★ 缓存模式详解:
writeback - 写入缓存，性能最佳 (有数据丢失风险)
writethrough - 写入即落盘，最安全 (性能较差)
none - 无缓存，直接IO
directsync - 同步直接IO
unsafe - 完全绕过缓存 (最快，最不安全)

★ 接口选择建议:
IDE - 最兼容 (Windows XP及更早)
SATA - 通用 (Windows 7/8)
VirtIO - 最佳性能 (需要驱动)
NVMe - 高性能 (v4.0+)
SCSI - 服务器场景
USB - 移动存储

★ 常见报错:
错误: "Could not open disk image"
原因: 文件不存在或权限不足
解决: 检查路径和权限

错误: "Unknown format"
原因: 格式不支持或未指定
解决: 指定format=参数

错误: "Device 'virtio-blk' not found"
原因: QEMU未编译virtio支持
解决: 使用其他接口如sata

错误: "Could not open backing file"
原因: 后端镜像丢失
解决: qemu-img rebase修复

3.2 -blockdev (高级块设备)
格式: -blockdev driver=DRIVER,node-name=NAME,...

★ 优点:

最精细的块设备控制

支持复杂存储拓扑

支持多种后端驱动

支持块设备快照

★ 缺点:

语法极其复杂

需要深入理解存储栈

初学者容易出错

某些驱动需要额外编译

★ 支持驱动:
file # 文件后端
qcow2 # QCOW2格式
raw # RAW格式
rbd # Ceph RBD
iscsi # iSCSI
nbd # NBD
gluster # GlusterFS
ssh # SSH
null # 空设备

★ 使用示例:

完整配置
-blockdev driver=file,node-name=disk0,filename=disk.qcow2
-blockdev driver=qcow2,node-name=disk0qcow2,file=disk0
-device virtio-blk-pci,drive=disk0qcow2

3.3 便捷简写
-hda file - IDE硬盘0 (最兼容)
-hdb file - IDE硬盘1
-hdc file - IDE硬盘2
-hdd file - IDE硬盘3
-cdrom file - IDE光驱 (IDE1 master)
-fda file - 软盘0
-fdb file - 软盘1

★ 优点: 简单直观，适合初学者
★ 缺点: 功能有限，无法精细控制
★ 历史: 最古老的参数，所有版本支持

四、启动参数 (-boot)
================================================================================

4.1 -boot (启动配置)
格式: -boot [order=drives][,once=drives][,menu=on|off][,splash=file][,splash-time=ms][,reboot-timeout=ms][,strict=on|off]

★ 优点:

灵活配置启动顺序

支持一次启动

可显示启动菜单

支持启动画面

★ 缺点:

某些组合不兼容

启动画面需要特定格式

★ 引导设备简写:
a = 软盘
c = 硬盘 (默认)
d = CD-ROM
n = 网络 (PXE)

★ 历史遗留:

v1.0: 只支持 -boot [a|c|d|n]

v1.5: 增加menu支持

v2.0: 增加once/order语法

v3.0: 增加splash支持

★ 使用建议:

从CD-ROM启动
-boot order=d

从硬盘启动，显示菜单
-boot order=c,menu=on

仅本次从CD-ROM启动
-boot once=d

-device ps2-mouse # PS/2鼠标

★ 历史遗留:

v1.0: 只有ps2-mouse

v1.5: 增加usb-mouse

v2.0: 增加usb-tablet

================================================================================
十、调试与监控参数 (-d, -D, -monitor, -qmp, -gdb)
================================================================================

10.1 -d (调试日志)
格式: -d item1,item2,...

★ 优点:

详细的调试信息

可组合多个项目

帮助定位问题

★ 缺点:

会产生大量输出

影响性能

某些项目需要特定编译选项

★ 调试项目:
cpu # CPU指令日志
exec # 指令执行
int # 中断日志
mmu # MMU日志
pci # PCI日志
qmp # QMP日志
usb # USB日志
all # 所有日志
guest_errors # 客户机错误
unimp # 未实现功能
trace:EVENT # 特定追踪事件

★ 使用建议:

基础调试
-d guest_errors

完整调试
-d cpu,exec,mmu,int

10.2 -D (日志文件)
格式: -D logfile
★ 优点: 持久化日志
★ 缺点: 文件可能很大

10.3 -monitor (监视器)
格式: -monitor stdio|telnet:port|unix:socket

★ 优点:

交互式控制

实时状态查询

可执行命令

★ 使用示例:
-monitor stdio
-monitor telnet:127.0.0.1:4444,server,nowait

10.4 -qmp (QMP协议)
格式: -qmp unix:socket,server,nowait|tcp:port

★ 优点:

标准管理接口

JSON协议

支持复杂操作

支持事件通知

★ 缺点:

需要编程使用

协议复杂

需要v1.0+

★ 使用示例:
-qmp unix:/tmp/qmp.sock,server,nowait

10.5 -gdb (GDB调试)
格式: -gdb tcp::port
★ 使用: -gdb tcp::1234 -S (启动时暂停)

11.1 -sandbox (沙箱模式)
格式: -sandbox on[,obsolete=allow][,elevateprivileges=allow|deny][,spawn=allow|deny][,resourcecontrol=allow|deny]

★ 优点:

增强安全性

限制系统调用

防止逃逸

★ 缺点:

某些功能受限

可能需要特权

v3.0+支持

★ 使用: -sandbox on

11.2 -snapshot (快照模式)
★ 优点:

不持久化写入

测试安全

性能较好

★ 缺点:

数据不保存

关闭后数据丢失

★ 使用: -snapshot

11.3 -drive readonly=on
★ 优点: 防止磁盘写入
★ 缺点: 系统可能无法启动

16.1 启动与初始化错误
┌─────────────────────────────────────────────────────────────────────────┐
│ 错误: Could not open '/path/to/file': Permission denied │

├─────────────────────────────────────────────────────────────────────────┤
│ 错误: qemu-system-x86_64: -machine: invalid option │
│ 原因: 旧版本不支持 -machine 语法 │
│ 解决: 使用 -M 替代（2013年前版本）或升级QEMU │
├─────────────────────────────────────────────────────────────────────────┤
│ 错误: qemu-system-x86_64: -accel: invalid option │
│ 原因: QEMU版本低于2.0 │
│ 解决: 使用 -enable-kvm 或 -accel tcg │
├─────────────────────────────────────────────────────────────────────────┤
│ 错误: qemu-system-x86_64: unsupported machine type │
│ 原因: 机器类型不存在或拼写错误 │
│ 解决: qemu-system-x86_64 -M help 查看可用类型 │
├─────────────────────────────────────────────────────────────────────────┤
│ 错误: qemu-system-x86_64: -cpu: invalid CPU model │
│ 原因: CPU型号不支持 │

└─────────────────────────────────────────────────────────────────────────┘

16.2 内存相关错误
┌─────────────────────────────────────────────────────────────────────────┐
│ 错误: unable to map backing store for guest RAM │

│ 解决: 减少内存分配 (-m 2048)，关闭KSM │
├─────────────────────────────────────────────────────────────────────────┤
│ 错误: Cannot allocate memory │
│ 原因: 系统内存不足 │
│ 解决: 增加swap空间，或关闭其他程序 │
├─────────────────────────────────────────────────────────────────────────┤
│ 错误: invalid memory size: XXXM │
│ 原因: 内存大小格式错误 │
│ 解决: 使用 -m 2048 而非 -m 2048M │
└─────────────────────────────────────────────────────────────────────────┘

16.3 磁盘与存储错误
┌─────────────────────────────────────────────────────────────────────────┐
